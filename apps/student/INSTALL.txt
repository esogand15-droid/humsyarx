هام‌زیار — کلاینت وب دانشجو
================================================================
نسخه: 0.4.0-P3        تاریخ: 1404-07-27 (2026-10-19)
مسیر سرو: /student/
موج‌های انجام‌شده: P1 (ورود) · P2 (کتابخانه) · P3 (ریدر)


۰) نصب — فقط extract کن، هیچ فایلی را ادیت نکن
----------------------------------------------------------------
بستهٔ zip  کامل است. محتوایش را در **ریشهٔ مخزن** extract کن و اجازه
بده فایل‌های هم‌نام overwrite شوند:

    api/main.py                    ← نسخهٔ نهایی کامل (overwrite)
    api/routers/web_library.py     ← جدید: کتابخانه (فقط خواندن)
    api/routers/web_reader.py      ← جدید: ریدر + پیشرفت مطالعه
    apps/student/                  ← کلاینت وب (سورس + dist آماده)

`api/routers/web_student.py` از موج P1 روی ریپوی تو هست؛ اگر نبود،
نسخهٔ نهایی‌اش را جدا می‌فرستم.

پایهٔ `main.py` این بسته = همان فایلی که الان روی گیت‌هاب است
(کامیت 4933cf8). تفاوت: فقط افزوده، صفر خط حذف یا تغییر.


۱) موج P3 — خواندن داخل اپ
----------------------------------------------------------------
فایل‌ها حالا داخل خود اپ باز می‌شوند: PDF (رندر با pdf.js روی canvas)،
ویدیو، ویس و تصویر — همه با پشتیبانی Range، پس seek روی فایل بزرگ کار
می‌کند.

سه اندپوینت تازه:

    GET /api/web/library/view-url/{scope}/{id}   آدرس امضاشدهٔ ریدر
    GET|PUT /api/web/library/progress/{scope}/{id}   نقطهٔ توقف
    GET /api/web/library/continue                «ادامهٔ مطالعه»

scope یکی از `res` (منابع علوم پایه) یا `ref` (کتاب مرجع) است.

⚠ نکتهٔ مهم: **رلهٔ تازه ساخته نشد.** همان پراکسی موجود مینی‌اپ
(`/api/resources/preview/...` و `/api/references/preview/...` با
`api/telegram_send.proxy_telegram_preview`) استفاده می‌شود؛ این فایل فقط
برای کاربر وب، آدرس امضاشدهٔ ۱۰ دقیقه‌ای صدور می‌کند. یعنی:

- توکن ربات تلگرام هرگز به مرورگر نمی‌رسد.
- فایل از سرور خود هامزیار عبور می‌کند (بدون VPN، بدون لینک تلگرام).
- گیت اشتراک، دامنهٔ دید و «جلسهٔ جایگزین‌شده» داخل همان `preview`
  دوباره بررسی می‌شوند — نه یک‌بار در ابتدا.
- اگر کسی آدرس را کپی کند، بعد از ۱۰ دقیقه کار نمی‌کند و به همان
  کاربر هم محدود است.

کالکشن تازه (فقط افزودنی): `reading_progress`
    {_id:"<uid>:<scope>:<file_id>", uid, scope, file_id, page, total,
     position, kind, updated_at}

آپسِرت با _id یکتا، پس دو تب هم‌زمان رکورد تکراری نمی‌سازند. پیشرفت
هر ۷۰۰ms پس از آخرین حرکت ذخیره می‌شود (debounce)، نه در هر فریم.

اگر فایلی فرمتش برای مرورگر مناسب نباشد (پاورپوینت، zip و …)، ریدر
همان پیام روشن مینی‌اپ را نشان می‌دهد: «نمایش این نوع فایل پشتیبانی
نمی‌شود». این حالت عادی است، نه خطا.

۱) این موج چه چیزی را وصل می‌کند
----------------------------------------------------------------
کتابخانه با **دادهٔ واقعی** بالا می‌آید: ترم → درس → جلسه → فایل،
به‌علاوهٔ کتاب مرجع: موضوع → کتاب → جلدها.

اندپوینت‌های تازه (همه GET، همه فقط خواندن):

    /api/web/library/state          وضعیت دو گیت: منابع و مرجع
    /api/web/library/terms          ترم‌ها + شمارش درس
    /api/web/library/lessons/{term}
    /api/web/library/sessions/{id}
    /api/web/library/files/{id}
    /api/web/library/search?q=
    /api/web/library/subjects
    /api/web/library/books/{id}
    /api/web/library/book-files/{id}

مهم: این‌ها **هیچ منطق محتوایی تازه‌ای ندارند**. هر پاسخ از همان
هندلرهای موجود مینی‌اپ گرفته می‌شود (api/routers/resources.py و
api/routers/references.py)، فقط با احراز هویت وب روی آن. نتیجه:

- دامنهٔ دید (intake) خودکار اعمال می‌شود؛ دانشجوی ترم دیگر، محتوای
  ترم تو را نمی‌بیند.
- جلسه/کتاب «جایگزین‌شده» (fork) همان‌طور که مینی‌اپ می‌بیند، وب هم
  می‌بیند.
- گیت اشتراک همان `core/access.py` است. اگر پالیسی `SUB_REQUIRED`
  بدهد، وب دقیقاً همان کد را می‌گیرد و صفحهٔ «مخصوص مشترکین» را
  نشان می‌دهد.
- اگر فردا قانونی عوض شود، وب و مینی‌اپ **با هم** عوض می‌شوند.

هیچ فیلد تازه‌ای در پاسخ‌ها ساخته نشده و هیچ کالکشن جدیدی برای
کتابخانه لازم نیست. تنها کالکشن‌های تازه، همان سه‌تای ورود (P1) است.


۲) چرا /student/ و نه /app/
----------------------------------------------------------------
در مخزن هامزیار /app/ مال مینی‌اپ تلگرام است (miniapp/dist). سرو
کلاینت وب روی همان پیشوند، مینی‌اپ را shadow می‌کرد.

    /student/*   کلاینت وب دانشجو     (این بسته)
    /app/*       مینی‌اپ تلگرام        (دست‌نخورده)
    /admin/*     پنل مدیریت            (دست‌نخورده)
    /api/*       FastAPI               (+ /api/web/*)

این ترتیب تست شده است: با همین mountها، /app/ همچنان مینی‌اپ و
/admin/ همچنان پنل را برمی‌گرداند.


۳) بعد از extract چه کاری لازم است؟ هیچ.
----------------------------------------------------------------
`apps/student/dist` داخل بسته است، پس Dockerfile نیازی به تغییر ندارد
و بعد از push، /student/ روی Railway کار می‌کند.

فقط اگر کد فرانت را عوض کردی، بیلد تازه بساز:

    cd apps/student
    npm install
    npm run build
    git add dist && git commit -m "build(web): rebuild student app" && git push


۴) متغیرهای محیطی (همه اختیاری — پیش‌فرض‌ها کار می‌کنند)
----------------------------------------------------------------
    TELEGRAM_TOKEN            از قبل در Railway هست؛ برای ارسال کد لازم است
    BOT_USERNAME              مثلاً HumsyarBot — دکمهٔ «پشتیبانی» در صفحهٔ گیت
    WEB_STUDENT_COOKIE        نام کوکی نشست (پیش‌فرض hy_student_session)
    WEB_STUDENT_SESSION_DAYS  عمر نشست (پیش‌فرض ۳۰)
    WEB_STUDENT_OTP_TTL_SEC   عمر کد ورود (پیش‌فرض ۳۰۰)
    WEB_STUDENT_OTP_MAX_ATTEMPTS  سقف تلاش کد (پیش‌فرض ۵)
    WEB_STUDENT_OTP_RESEND_SEC    فاصلهٔ ارسال دوباره (پیش‌فرض ۶۰)
    WEB_STUDENT_COOKIE_SECURE     پیش‌فرض ۱ (روی HTTPS درست)
    WEB_STUDENT_PREFIX        پیش‌فرض /student
    WEB_AUTH_DEBUG            پیش‌فرض ۰. اگر ۱ باشد کد ورود در پاسخ API
                              برمی‌گردد — **هیچ‌وقت روی production نه**.

هیچ متغیر تازه‌ای برای P2 لازم نیست؛ کتابخانه از همان گیت موجود
استفاده می‌کند.


۵) کالکشن‌های تازه
----------------------------------------------------------------
P1:  web_login_challenges · web_sessions · web_auth_events
P2:  هیچ — کتابخانه کالکشن تازه ندارد (فقط می‌خواند).
P3:  reading_progress

ایندکس‌ها در اولین درخواست ساخته می‌شوند. هیچ مهاجرت یا backfill لازم نیست.


۶) تست ۳ دقیقه‌ای بعد از deploy
----------------------------------------------------------------
۱. /student/ → ورود با یوزرنیم یا شمارهٔ دانشجویی، کد از ربات.
۲. تب «کتابخانه» → باید ترم‌های ورودی خودت را ببینی، با شمارش درس.
۳. ترم → درس → جلسه → فایل: نام، نوع و حجم هر فایل.
۴. تب «مرجع» → موضوع → کتاب → جلدهای فارسی و انگلیسی.
۵. روی یک جزوه بزن → باید داخل اپ باز شود و با فلش‌ها صفحه عوض شود.
۶. اپ را ببند و دوباره باز کن → کارت «ادامهٔ مطالعه» بالای کتابخانه،
   همان فایل و همان صفحه را نشان می‌دهد.
۷. اگر کاربرت اشتراک فعال ندارد: به‌جای فهرست، پیام «مخصوص مشترکین»
   با کد `SUB_REQUIRED` می‌بینی. این درست است، نه باگ.

اگر فهرست خالی بود:
    - «هنوز ترمی برای تو ثبت نشده» یعنی intake کاربر با intake محتوا
      یکی نیست. intake کاربر را در پنل چک کن.
    - اگر ۴۰۱ گرفتی، نشست منقضی شده؛ دوباره وارد شو.


۷) چه چیزی در این موج عمداً انجام نشد
----------------------------------------------------------------
- هایلایت و یادداشت روی متن جزوه (مرکب/قلم): فاز P4. ریدر فعلاً
  می‌خواند و جای توقف را نگه می‌دارد، ولی لایهٔ حاشیه‌نویسی ندارد.
- دانلود آفلاین: فاز P9 (PWA). «آفلاین» یعنی فایل ذخیره روی دستگاه؛
  برای محتوای اشتراکی عمداً در فاز جداگانه تصمیم‌گیری می‌شود.
- جستجوی سراسری در نوار بالا: اندپوینت `/library/search` آماده است،
  ولی صفحهٔ جستجو در فاز بعد باز می‌شود.
- گیت اشتراک روی بقیهٔ صفحه‌ها: همچنان سمت سرور در core/access.py.
