هامزیار — کلاینت وب دانشجو · موج P1 (ورود)
================================================================
نسخه: 0.2.0-P1        تاریخ: 1404-07-27 (2026-10-19)
مسیر سرو: /student/    ← نه /app/ (توضیح پایین)


۱) این بسته چه چیزی را اضافه می‌کند
----------------------------------------------------------------
    api/routers/web_student.py      ← تنها فایل جدید سمت بک‌اند
    apps/student/                   ← کلاینت وب (سورس + بیلد آماده)

هیچ فایل موجودی بازنویسی نمی‌شود. تنها کاری که تو می‌کنی، سه خط
افزودن به api/main.py است (بخش ۳).


۲) چرا /student/ و نه /app/   ← مهم‌ترین نکتهٔ این نسخه
----------------------------------------------------------------
در مخزن هامزیار، مسیر /app/ از قبل مال مینی‌اپ تلگرام است
(miniapp/dist). اگر کلاینت وب را روی /app/ می‌گذاشتیم، مینی‌اپ
دیده نمی‌شد. پس namespace نهایی روی دامنه این است:

    /student/*   کلاینت وب دانشجو     (این بسته)
    /app/*       مینی‌اپ تلگرام        (دست‌نخورده)
    /admin/*     پنل مدیریت            (دست‌نخورده)
    /api/*       FastAPI               (فقط یک روتر جدید)


۳) نصب — سه خط در api/main.py
----------------------------------------------------------------
الف) کنار بقیهٔ importهای روترها (حدود خط ۱۷):

    from api.routers import web_student

ب) کنار بقیهٔ include_routerها (بعد از web_admin):

    app.include_router(web_student.router, prefix="/api/web", tags=["web-student"])

ج) **پایین‌ترین جای فایل**، بعد از mountهای /admin و /app:

    web_student.mount(app)

اگر مرحلهٔ (ج) را قبل از mountهای دیگر بگذاری، ترتیب تطبیق مسیر
FastAPI عوض می‌شود. آخرین دستور فایل باشد.


۴) بیلد فرانت
----------------------------------------------------------------
پوشهٔ apps/student/dist در همین بسته هست، پس بعد از push روی Railway
مسیر /student/ بلافاصله کار می‌کند و لازم نیست Dockerfile را تغییر بدهی.

اگر بعداً کد فرانت را عوض کردی، بیلد تازه بساز:

    cd apps/student
    npm install
    npm run build
    git add dist && git commit -m "build(web): rebuild student app" && git push

(چرا dist کامیت می‌شود: مرحلهٔ frontend در Dockerfile فقط miniapp و
webadmin را می‌سازد. اگر نمی‌خواهی dist در گیت باشد، این ۶ خط را در
مرحلهٔ ۱ همان Dockerfile اضافه کن و خط dist را از .gitignore بردار:

    COPY apps/student/package.json apps/student/package-lock.json ./apps/student/
    RUN npm --prefix ./apps/student ci --no-audit --no-fund --fetch-retries=5
    COPY apps/student/ ./apps/student/
    RUN npm --prefix ./apps/student run build
    # و در runtime stage:
    COPY --from=frontend /build/apps/student/dist ./apps/student/dist
)


۵) متغیرهای محیطی (همه اختیاری — پیش‌فرض‌ها کار می‌کنند)
----------------------------------------------------------------
    TELEGRAM_TOKEN            از قبل در Railway هست؛ برای ارسال کد لازم است
    BOT_USERNAME              مثلاً HumsyarBot — برای دکمهٔ «پشتیبانی» و لینک ربات
    WEB_STUDENT_COOKIE        نام کوکی نشست (پیش‌فرض hy_student_session)
    WEB_STUDENT_SESSION_DAYS  عمر نشست (پیش‌فرض ۳۰، بازه ۱..۱۸۰)
    WEB_STUDENT_OTP_TTL_SEC   عمر کد ورود (پیش‌فرض ۳۰۰)
    WEB_STUDENT_OTP_MAX_ATTEMPTS  سقف تلاش کد (پیش‌فرض ۵)
    WEB_STUDENT_OTP_RESEND_SEC    فاصلهٔ ارسال دوباره (پیش‌فرض ۶۰)
    WEB_STUDENT_COOKIE_SECURE     پیش‌فرض ۱ (روی HTTPS درست). فقط برای
                                  تست محلی روی http آن را ۰ کن، وگرنه
                                  مرورگر کوکی Secure را ذخیره نمی‌کند.
    WEB_STUDENT_PREFIX        پیش‌فرض /student
    WEB_AUTH_DEBUG            پیش‌فرض ۰. اگر ۱ باشد کد ورود در پاسخ API
                                  برمی‌گردد — **هیچ‌وقت روی production نه**.

اگر TELEGRAM_TOKEN نباشد، سرور خطا نمی‌دهد و سرویس بالا می‌ماند، ولی
کد ورود فرستاده نمی‌شود و کاربر پیام روشن می‌گیرد. هرگز کدی در پاسخ
داده نمی‌شود مگر WEB_AUTH_DEBUG=1.


۶) کالکشن‌های تازه (فقط افزودنی — هیچ سند موجودی تغییر نمی‌کند)
----------------------------------------------------------------
    web_login_challenges   چالش‌های کد یک‌بارمصرف (TTL خودکار)
    web_sessions           سشن‌ها (توکن فقط هش‌شده؛ TTL خودکار)
    web_auth_events        ثبت ورود/خروج و تلاش ناموفق (بدون کد/توکن)

ایندکس‌ها در اولین درخواست ساخته می‌شوند. هیچ مهاجرت و backfill لازم نیست.


۷) چطور تست کنم (۲ دقیقه)
----------------------------------------------------------------
۱. بعد از deploy، آدرس /student/ را باز کن → صفحهٔ ورود.
۲. یوزرنیم تلگرام یا شمارهٔ دانشجویی یکی از کاربران ثبت‌شده را بزن.
۳. کد باید در چت ربات هامزیار بیاید؛ وارد کن → وارد اپ می‌شوی.
۴. صفحه /student/me باید نام و شمارهٔ دانشجویی خودت را نشان دهد.
۵. تب «خروج از حساب» → برگشت به صفحهٔ ورود.

اگر کد نیامد:
    - /student/ → /api/web/auth/config باید 200 بدهد. اگر 404 داد،
      مرحلهٔ (ب) نصب انجام نشده.
    - /student/ اگر 503 داد، یعنی apps/student/dist در گیت نیست.
    - اگر کد آمد ولی «کد نادرست» گرفتی، ساعت سرور را با NTP چک کن؛
      کد ۵ دقیقه اعتبار دارد.

نکته: اگر حساب کاربر approved نباشد، عمداً وارد اپ نمی‌شود و صفحهٔ
«در انتظار تأیید» می‌بیند؛ این رفتار درست است، نه باگ.


۸) چه چیزی در این موج عمداً انجام نشد
