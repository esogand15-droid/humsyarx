هامزیار — کلاینت وب دانشجو · موج P1 (ورود)

مسیر سرو: /student/


۰) نصب چطور انجام می‌شود — هیچ فایلی را دستی ادیت نکن
----------------------------------------------------------------
این بسته **همهٔ فایل‌های لازم را کامل دارد**، از جمله نسخهٔ نهایی
api/main.py. کافی است محتوای zip را در ریشهٔ مخزن extract کنی و
اجازه بدهی فایل‌های هم‌نام overwrite شوند:

    api/main.py                  ← کامل، با سه اتصال لازم (overwrite)
    api/routers/web_student.py   ← فایل جدید
    apps/student/                ← پوشهٔ جدید (سورس + dist آماده)

هیچ ادیت دستی، هیچ paste، هیچ patch لازم نیست.

⚠ یک شرط: فایل main.py این بسته از کامیت
    71db567e (2026-10-18 16:58 «Add files via upload»)
ساخته شده است. اگر بعد از این کامیت main.py را خودت تغییر داده‌ای،
اجازه نده overwrite شود — بگو تا نسخهٔ نهایی را روی main.py خودت
بسازم. سه تغییر این بسته در main.py فقط این‌ها هستند:

    ۱) خط ~۴۵:   web_student,             (در بلوک import روترها)
    ۲) خط ~۴۸۵:  app.include_router(web_student.router, prefix="/api/web", ...)
    ۳) خط آخر:   web_student.mount(app)

اگر باز هم ترجیح می‌دهی main.py خودت دست‌نخورده بماند، فقط دو
تغییر (۱) و (۲) و (۳) را همان‌جا اضافه کن؛ رفتار یکسان است.


۱) چرا /student/ و نه /app/
----------------------------------------------------------------
در مخزن هامزیار، /app/ از قبل مال مینی‌اپ تلگرام است (miniapp/dist).
سرو کلاینت وب روی همان پیشوند، مینی‌اپ را shadow می‌کرد. namespace
نهایی روی دامنه:

    /student/*   کلاینت وب دانشجو     (این بسته)
    /app/*       مینی‌اپ تلگرام        (دست‌نخورده)
    /admin/*     پنل مدیریت            (دست‌نخورده)
    /api/*       FastAPI               (+ /api/web/*)

این ترتیب تست شده است: با همان ترتیب mountهای main.py، درخواست به
/app/ همچنان مینی‌اپ و /admin/ همچنان پنل را برمی‌گرداند.


۲) بعد از extract چه کاری لازم است؟ هیچ.
----------------------------------------------------------------
پوشهٔ apps/student/dist داخل بسته است، پس Dockerfile نیازی به تغییر
ندارد و بعد از push، مسیر /student/ روی Railway کار می‌کند.

فقط اگر بعداً کد فرانت را عوض کردی، بیلد تازه بساز:

    cd apps/student
    npm install
    npm run build
    git add dist && git commit -m "build(web): rebuild student app" && git push


۳) متغیرهای محیطی (همه اختیاری — پیش‌فرض‌ها کار می‌کنند)
----------------------------------------------------------------
    TELEGRAM_TOKEN            از قبل در Railway هست؛ برای ارسال کد لازم است
    BOT_USERNAME              مثلاً HumsyarBot — دکمهٔ «پشتیبانی» و لینک ربات
    WEB_STUDENT_COOKIE        نام کوکی نشست (پیش‌فرض hy_student_session)
    WEB_STUDENT_SESSION_DAYS  عمر نشست (پیش‌فرض ۳۰، بازه ۱..۱۸۰)
    WEB_STUDENT_OTP_TTL_SEC   عمر کد ورود (پیش‌فرض ۳۰۰)
    WEB_STUDENT_OTP_MAX_ATTEMPTS  سقف تلاش کد (پیش‌فرض ۵)
    WEB_STUDENT_OTP_RESEND_SEC    فاصلهٔ ارسال دوباره (پیش‌فرض ۶۰)
    WEB_STUDENT_COOKIE_SECURE     پیش‌فرض ۱ (روی HTTPS درست)
    WEB_STUDENT_PREFIX        پیش‌فرض /student
    WEB_AUTH_DEBUG            پیش‌فرض ۰. اگر ۱ باشد کد ورود در پاسخ API
                              برمی‌گردد — **هیچ‌وقت روی production نه**.

اگر TELEGRAM_TOKEN نباشد، سرویس بالا می‌ماند ولی کد فرستاده نمی‌شود
و کاربر پیام روشن می‌گیرد. هیچ کدی در پاسخ برنمی‌گردد مگر
WEB_AUTH_DEBUG=1.


۴) کالکشن‌های تازه (فقط افزودنی — هیچ سند موجودی تغییر نمی‌کند)
----------------------------------------------------------------
    web_login_challenges   چالش‌های کد یک‌بارمصرف (TTL خودکار)
    web_sessions           سشن‌ها (توکن فقط هش‌شده؛ TTL خودکار)
    web_auth_events        ثبت ورود/خروج و تلاش ناموفق (بدون کد/توکن)

ایندکس‌ها در اولین درخواست ساخته می‌شوند. هیچ مهاجرت یا backfill لازم نیست.


۵) تست ۲ دقیقه‌ای بعد از deploy
----------------------------------------------------------------
۱. /student/ را باز کن → صفحهٔ ورود.
۲. یوزرنیم تلگرام یا شمارهٔ دانشجویی یکی از کاربران ثبت‌شده را بزن.
۳. کد باید در چت ربات هامزیار بیاید؛ وارد کن → وارد اپ می‌شوی.
۴. /student/me باید نام و شمارهٔ دانشجویی خودت را نشان دهد.
۵. «خروج از حساب» → برگشت به صفحهٔ ورود.

اگر صفحهٔ ورود نیامد:
    /api/web/auth/config باید 200 بدهد. 404 → main.py قدیمی مانده.
    /student/ اگر 503 داد → apps/student/dist در گیت نیست.
اگر کد آمد ولی «کد نادرست» گرفتی، ساعت سرور را چک کن (کد ۵ دقیقه اعتبار دارد).

حساب تأییدنشده عمداً وارد اپ نمی‌شود و صفحهٔ «در انتظار تأیید» می‌بیند؛
این رفتار درست است، نه باگ.
